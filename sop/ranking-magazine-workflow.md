# SOP — ランキング系マガジンの制作フロー（開発2・3・4部 共通）

頻度が違うだけで手順は同じ。3部=週次、2部・4部=月次。

## 0. 事前（各部で1回だけ）

- データソースを確定（`dev/<部>/sources.md`、規約確認済み）
- 提携アフィリ案件を1つ以上決定
- 「独自の切り口」を1つ決めて README に明記（AIに任せない差別化ポイント）

## 1. データ収集（開発3部は `pipeline/collect.py` が自動）

- 一次ソースから今期のデータを取得
- `dev/<部>/data/<期間>.json`（または .csv）に保存。**出典URLと取得日を必ず含める**
- 他サイトのランキング表は転載しない。数値は引用の範囲
- 開発3部: レビューで作品を落とす→`data/inputs/<週>.drop.json`、誤って要確認になった作品を確定→`data/inputs/<週>.confirm.json` を置いて **collect.py を再実行**（`inputs/README.md`）
- ⚠️ **collect.py の再実行は「データ・PNGの確定」まで。手順3で分析を書き込んだ後は絶対に再実行しない**（`drafts/<週>.md` が上書きされ分析が消える）

## 2. ドラフト生成（`ranking-writer` エージェント / または Claude Code に直接依頼）

入力: 今期データ（`data/<週>.json`）、前週の `published/` 記録、README の「独自の切り口」
出力（`dev/<部>/drafts/<期間>.md` の `【ranking-writer 記入】` 箇所を埋める）:
- 各作品の「人気の理由」（事実＋指標の動き）
- 「今週の定点観測」（独自の切り口ブロック）
- 「来週の注目」
- あらすじは公式ベースで2〜3文に書き直し、`※TMDB由来…` の行を削除
- SNS文面 3〜5本（`marketing/threads/queue.md` 追記用、種別=誘導）
- 開発3部の PNG（`drafts/<週>.png`）はそのまま使う（手順1で確定済み）

## 3. 社長レビュー（公開前・必須）

- [ ] 順位・固有名詞・数値が出典と一致するか（1件ずつ照合）
- [ ] 考察に事実誤認・断定しすぎがないか
- [ ] ネタバレ配慮（ドラマ）／誤解を招く表現がないか
- [ ] 冒頭に広告表記（`sop/disclosure.md`）
- [ ] アフィリンクが記事内容と関係し、数を絞れているか（`sop/affiliate-rules.md`）
- [ ] 末尾に「次回予告」＋「開発1部の有料note」への1行導線

## 4. 公開

- `sop/publish-note.md` に沿ってnote公開、マガジンに追加
- draft を `dev/<部>/published/<期間>.md` に移し、URL・公開時刻を追記

## 5. 引き渡し・記録

- SNS文面が `marketing/threads/queue.md` に入っていることを確認
- 公開24〜48時間後の初速（閲覧・スキ・アフィリクリック）を `published/<期間>.md` にメモ
- 週次締めで `finance/kpi.csv` に反映

## 品質の下限

- 出典ゼロの数値を載せない
- 「AIが書いた一般論」だけの考察は不可。必ず「独自の切り口」ブロックを入れる
