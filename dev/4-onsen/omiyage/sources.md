# 開発4部 お土産ランキング — データソース（確定版 v1）

温泉宿ランキング（`dev/4-onsen/sources.md`）の型をそのまま流用。対象を「宿」から
「その月のエリアの定番お土産（お菓子・特産品）」に置き換えただけ。決定経緯: `docs/decisions/0004`（お土産の節）。

## クレーム

- ○「〔エリア〕のお土産ランキングTOP5（独自採点）」「レビュー評価が高い順」
- ✕「一番人気」「絶対おすすめ」等の断定。✕ 実際に食べたかのような体験談

## 独自採点の定義

**楽天市場のレビュー評価 ＋ Amazonのレビュー評価（各5点満点）の単純平均**を独自採点とする。

| 要素 | ソース | 備考 |
|---|---|---|
| A: 楽天市場評価 | 当該商品の楽天市場 商品ページの総合評価点・レビュー件数 | 5点満点。URLを出典として明記 |
| B: Amazon評価 | 当該商品の Amazon 商品ページの星評価・評価件数 | 5点満点。URLを出典として明記 |

- **対象条件**: A・Bの両方が取得できる商品のみ。各サイトで**レビュー20件未満**は対象外。
- 独自採点 = `(A + B) / 2`（小数第2位で四捨五入、表示は小数第1位）。表にA/Bの内訳（点数・件数）を併記。
- 「その月のエリアの定番お土産」を10〜15件リストアップ → 上記条件でスクリーニング → 独自採点でTOP5。
- **同一ブランドの別商品が複数入らないよう**、1ブランド1商品まで（同点なら評価件数が多い方）。

## 口コミの要約ルール（温泉宿と同じ）

- 一人称の体験談として書かない。「レビューでは〜という声が多い」「一方で〜という指摘も」の第三者要約。
- 特定レビューの丸写し不可。複数レビューに共通する傾向を自分の言葉で。
- 良い点・残念な点はそれぞれ最低1つ、事実（レビューの傾向）に基づいて。無理に作らない。
- 見るポイントの例: 味／甘さ・塩気／日持ち・賞味期限／個包装の有無／サイズ・量／価格の割安感／
  配りやすさ／贈答向きか／季節・数量限定か。

## 項目別ソース

| 記事に載せる項目 | ソース | 注意 |
|---|---|---|
| 独自採点（A/B内訳） | 上表 | 出典URL・取得日を必ず記録 |
| 商品の基本情報（製造元・特徴・入手先） | メーカー公式 or 楽天/Amazonの掲載情報 | 一次情報を優先 |
| 良いところ・残念なところ | 楽天市場／Amazonのレビュー | 丸写し禁止・体験談化禁止 |
| 価格帯 | 楽天/Amazonの掲載価格（変動あり） | 「〇〇円前後（取得時点）」と明記。時期変動を注記 |
| こんな人におすすめ | 上記からの合成（考察） | 意見と分かる書き方で |

## アフィリエイト対応

**温泉宿ランキングと同じリンクを使う**（社長方針 2026-09-10）。`dev/4-onsen/affiliates.json` の
`generic`（楽天トラベル・じゃらんnet・JTB旅物語）を末尾に置き、「現地で買う旅に出るなら」という文脈でつなぐ。

- 個別商品の楽天市場リンク: 楽天アフィリエイト（開発4部で提携済み）は**楽天市場の商品リンクも作れる**ため、
  各お土産に個別リンクを付けられる。発行が要るので、TOP5確定後に `drafts/YYYY-MM.md` へ直接埋める
  （温泉宿の個別宿リンクと同じ運用）。当面はテキスト表記＋末尾の汎用リンクのみでも可。
- 冒頭に広告表記（`sop/disclosure.md`）。リンクを1つでも含む号は必須。
