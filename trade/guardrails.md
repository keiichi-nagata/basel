## ハード上限（社長が実数を入れる）— v1.1: 複数銘柄・前場完結・信用取引（日計り）

| 項目 | 値 | メモ |
|---|---|---|
| 購入件数の上限 | 【要確認】件 | `stock-app` の順位上位からこの件数まで採用。候補が少ない日は少ない件数（0件もあり） |
| 市場フィルタの初期値 | 【要確認】（すべて／スタンダード／プライム／グロース） | `stock-app` の銘柄区分でフィルタしてから順位上位を採用 |
| 1銘柄あたりの予算額（委託保証金） | 【要確認】円 | **株数はここから逆算**: floor(予算額÷始値÷100)×100株。100株も買えない銘柄はその日は見送り。生活防衛資金と分離、全損しても生活に影響しない額から |
| 1日の想定最大投入額 | 予算額 × 購入件数上限（円） | 全銘柄が約定した場合の目安。この額を基準に「1日の最大損失額」を決める |
| 買い指値の置き方 | 【要確認】 | 始値そのもの／始値 +【要確認】% まで許容。これを超える価格では買わない |
| 利確ライン（売り指値） | 始値 +【要確認】% | 例: +3%（`stock-app` 管理画面デフォルト）。指値価格の丸め方は`strategy.md`の呼値の注意点を参照 |
| 損切りライン（逆指値） | 始値 −【要確認】% | 例: −2%。**1トレードの最大損失＝建玉サイズ（予算額×レバレッジ）×この% を超えない**（保証金額基準にしない） |
| ギャップアップの許容上限 | 前日終値比 +【要確認】% まで | これ以上ギャップしていたら寄り天リスクで**当日見送り**（銘柄単位） |
| 決済セッション | 前場固定（11:15の【要確認】分前に成行） | v1.1は前場のみ。設定上は後場(15:15)も選べる作りだが当面使わない |
| 1日の最大損失額（キルスイッチ） | 【要確認】円 | 保有中の全銘柄の含み損合計がこれに達したら**残る建玉をすべて**成行決済して当日終了 |
| 週の最大損失額 | 【要確認】円 | 到達したら週末まで停止、原因を `journal/` に記録してから再開 |
| 対象から外す | 決算発表日・ストップ高安張り付き・値幅制限で売買不可・板が薄い銘柄・**信用取引不可銘柄** | bot 側で二重チェック（銘柄ごと） |
| 1日の最大発注回数 | 【要確認】 | 新規＋決済＋訂正。kabuステーションAPIの流量制限（発注5件/秒）に加え、**規約上「同一銘柄への注文は現物・信用・執行条件を問わず5件が上限」**（利用規定第3条18項）。銘柄数が増えるほど合計の発注数も増えるので、購入件数上限と合わせて見積もる |
| kabuステーションの「ソフトリミット」（ワンショット上限） | 【要確認】円 | システム設定 > API 画面で設定するbroker側のハード制限（現状デフォルト300万円）。**上の「1銘柄あたりの予算額」の数倍程度まで下げる**。botのバグで桁を間違えても機械的に止まる多重防御 |

## 信用取引固有のガードレール（2026-09-12追加。当初「現物」としていたのを訂正）

現物にはない、レバレッジ・追証のリスクに対応する。

| 項目 | 値 | メモ |
|---|---|---|
| 委託保証金率／実質レバレッジ上限 | 【要確認】 | 建玉サイズ＝委託保証金÷保証金率。上の損切り%はこの建玉サイズに対して計算する |
| 追証（保証金維持率）ライン | 【要確認】% | eスマート証券の基準を転記。**キルスイッチはこのラインよりずっと手前**で発動するように余裕を持たせる |
| 制度信用／一般信用の別 | 【要確認】 | 対象銘柄が信用取引可能かをbot側の除外条件に追加（`stock-app`のスクリーニングと二重化） |
| 日計り信用の手数料・金利（品貸料） | 【要確認】 | 前場のみで手仕舞うため金利はほぼ想定外だが、eスマート証券の日計り信用の手数料体系を確認して記入 |

## 運用ルール

- **キルスイッチ発動時**: 当日は再開しない。翌営業日に日誌へ原因を書いてから稼働。
- **API/データ異常時**（接続断・気配取得失敗・想定外レスポンス）: 新規発注を止め、保有はルール通り決済。
- **相場急変時**（サーキットブレーカー、指数の急落など）: 新規停止。判断は社長。
- パラメータ（上限・戦略）の変更は、変更内容・理由・前後の想定を社長が承認してから反映。変更履歴を下に残す。
- 週次で成績（勝率・損益・最大ドローダウン・約定数）をレビューし `journal/` に記録。
