## ハード上限（社長が実数を入れる）

| 項目 | 値 | メモ |
|---|---|---|
| 運用に回す総資金 | 【要確認】円 | 生活防衛資金と分離。全損しても生活に影響しない額 |
| 1銘柄あたりの最大投入額 | 【要確認】円 | 総資金の◯%以内 |
| 同時保有銘柄数の上限 | 【要確認】 | 分散のため |
| 1日の最大損失額（キルスイッチ） | 【要確認】円 | 当日の実現＋含み損がこれに達したら**全決済して当日停止** |
| 週の最大損失額 | 【要確認】円 | 到達したら週末まで停止し、原因を `journal/` に記録してから再開 |
| 稼働時間帯 | 【要確認】 | 例: 前場のみ（9:00〜11:30）／ザラ場全体 |
| 対象銘柄 | 【要確認】 | 例: プライムの売買代金上位◯銘柄。値がさ・低流動性・新興は除外 |
| 1注文あたりの上限株数／金額 | 【要確認】 | スリッページ・約定リスク対策 |
| 1日の最大約定回数 | 【要確認】 | API規約の発注頻度制限内に収める |

## 運用ルール

- **キルスイッチ発動時**: 当日は再開しない。翌営業日に日誌へ原因を書いてから稼働。
- **API/データ異常時**（接続断・気配取得失敗・想定外レスポンス）: 新規発注を止め、保有はルール通り決済。
- **相場急変時**（サーキットブレーカー、指数の急落など）: 新規停止。判断は社長。
- パラメータ（上限・戦略）の変更は、変更内容・理由・前後の想定を社長が承認してから反映。変更履歴を下に残す。
- 週次で成績（勝率・損益・最大ドローダウン・約定数）をレビューし `journal/` に記録。
