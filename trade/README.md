# トレード部 — 自動デイトレード（自己資金運用）

## これは何か

kabuステーションAPI（三菱UFJ eスマート証券）を使った完全自動デイトレードの**運用**を担う部門。
収益源は相場での売買損益（自己資金・自分の口座のみ）。決定経緯: `docs/decisions/0005-trade-dept-auto-daytrade.md`。

- **この部の担当**: 戦略メモ、リスク上限（ガードレール）の明文化、運用日誌、週次レビュー
- **この部が扱わないもの**:
  - bot 本体コード・kabuステーションAPI認証情報・実行環境 → **`投資` monorepo の `daytrade-bot/`**
    （`stock-app` と同じ場所。アプリの選定ロジックを直接呼べる）。認証情報は `daytrade-bot/.env`（git管理外）
  - やり方を売る有料note（「おすすめ株アプリの作り方」「デイトレ完全自動化のやり方」）→ **開発1部**（`dev/1-apps/catalog.md` #7-8）
  - 構築記録・実績の SNS 発信 → マーケ部

## 仕組みの全体像（v1）

**1日1銘柄・前場だけで完結**。`stock-app`（毎朝 JST 7:00 におすすめ株を1銘柄選定）→ Supabase
`recommendations` → `daytrade-bot` が 9:00 に始値を確認して指値買い＋損切り逆指値 → 利確/損切りが
当たらなければ 11:30 の前場引けで成行決済（`strategy.md`）。kabuステーションと bot は**この
Claude Code が動く PC**で常時起動（`kabu-api-notes.md`）。Claude/エージェントは発注・稼働操作をしない。

## 絶対ルール（CLAUDE.md より）

- 自動発注は、**社長が承認した戦略と `guardrails.md` のリスク上限の範囲内**でのみ専用スクリプトが実行する。
- リスク上限の変更、bot の稼働／停止の切替は**社長承認必須**。
- **エージェント・Claude Code はコード・戦略のドラフトと運用日誌の作成のみ**。発注・パラメータ変更・
  稼働切替・APIキーの取り扱いは一切しない。

## フォルダ

- `guardrails.md` — リスク上限（1銘柄上限・日次最大損失＝キルスイッチ・稼働時間・対象銘柄・運用総資金）。**社長が数値を確定する**
- `strategy.md` — 売買の根拠、シグナル源（`stock-app`）、エントリー／エグジット条件（v1たたき台）
- `kabu-api-notes.md` — kabuステーションAPI の制約メモ（トークン・レート制限・常時起動要件・規約リンク）
- `journal/YYYY-MM.md` — 日次・週次の運用日誌（約定・損益・気づき・不具合）。テンプレは `journal/_TEMPLATE.md`
- `published/` — 実績サマリ（月次）。SNS/note で公開した数値の記録

## 経理

- 売買損益は Basel の事業損益として管理するが、**確定申告の所得区分（事業所得 / 譲渡所得＝申告分離課税）は
  税理士に確認**（`docs/decisions/0005`）。株のデイトレ益を事業所得と認めさせるハードルは高い。
- `finance/` では SNS 事業の売上・経費と分けて集計する（`finance/README.md`）。

## 立ち上げの宿題（社長）

1. 三菱UFJ eスマート証券の口座開設 → kabuステーションのDL → API有効化・APIキー発行
2. `guardrails.md` の `【要確認】` を実数で確定（運用総資金・1銘柄上限・日次最大損失・稼働時間・対象銘柄）
3. `daytrade-bot/` を `投資` monorepo に作成。認証情報は `daytrade-bot/.env`（git管理外）
4. bot を動かす常時起動Windows環境の用意（kabuステーションが起動している必要がある）
5. kabuステーションAPI 利用規定PDFを通読（自動売買の条件・禁止事項）
6. 税理士に所得区分（事業所得 / 譲渡所得）を相談
7. まず「発注しないログモード」で数日 → 最小ロットで実発注 → 日誌をつけながら段階的に上限を上げる
