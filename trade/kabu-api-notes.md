# kabuステーションAPI メモ（規約確認の下地）

出典を必ず一次で確認すること。ここは調査メモ。最終確認日: 2026-09-10（WebSearch）

## サービス概要

- 三菱UFJ eスマート証券（旧 auカブコム証券）の個人向けAPI。**プログラムによる全自動取引は規約上OK**。
- 公式: https://kabu.com/item/kabustation_api/default.html ／ APIドキュメント: https://kabucom.github.io/kabusapi/
- 利用規定PDF: https://kabu.com/pdf/Gmkpdf/service/kabustationapiuserpolicy.pdf （**運用開始前に社長が通読**）

## 動作の前提（重要な運用制約）

- APIは**デスクトップアプリ「kabuステーション」経由**で動く（ローカルの `localhost:18080` 等にリクエスト）。
  → **bot を動かすマシンで kabuステーションが常時起動している必要がある**。完全クラウド運用はできず、
  Windows マシン（または常時起動のWindows環境）が要る。ここが `stock-app`（GitHub Actions で完結）と違う点。
- APIキー/パスワードは kabuステーション側の「システム設定 > API」で有効化して発行。

## 認証・トークン

- トークンは**発行から24時間有効**、毎朝**6:15頃に自動リフレッシュ**。
- kabuステーションの終了・ログアウト・別トークン発行・早朝の強制ログアウトで**無効化**される。
  → bot は「トークン失効を検知したら再取得」する実装が必須。

## レート制限

- **発注API: 5件/秒**
- 取引余力API・情報API・銘柄登録API: 10件/秒
- ほかに**流量制限**（一定時間内の発注件数制限）あり。`guardrails.md` の「1日の最大約定回数」は
  この範囲に収める。

## 実装で気をつける（ネット記事で頻出）

- **二重発注の防止**（接続断・リトライで同じ注文を2回出さない。注文IDで冪等に）
- トークン取得の設計（毎回取り直すと無駄。キャッシュ＋失効検知）
- 現物／信用で発注パラメータが異なる。v1は**現物**で。
