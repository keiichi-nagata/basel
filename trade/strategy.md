# トレード部 — 戦略メモ

売買の根拠をここに残す。実装は別リポの bot 本体（`投資` monorepo の `daytrade-bot/`、`stock-app` と同じ場所）。
**Claude Code / trade-ops は戦略・コードのドラフトまで。発注はしない。**

## 全体像（v1・社長の方針 2026-09-10）

**1日1銘柄・前場だけで完結**するシンプルな順張りデイトレを自動化する。

| 時刻 | 何をする |
|---|---|
| 7:00 | `stock-app` が **おすすめ株を1銘柄** 選定（`recommendations` に1件）。スコア＝直近5営業日モメンタム＋出来高急増度、フィルタ＝5日MA>20日MA・RSI14<70・直近採用済み除外 |
| 9:00〜 | bot が **始値を確認** → 始値を基準に、**買い指値**と**損切り逆指値**を出して新規買い（サイズは `guardrails.md`）。約定しなければ当日は見送り（追いかけない） |
| 約定後 | **利確の売り指値**（始値 +X%）と **損切りの逆指値**（始値 −Y%）を置く。X/Y は `guardrails.md` で社長が指定 |
| 11:30（前場引け） | 利確・損切りどちらも当たっていなければ、**成行で決済**（前場のみで完結・オーバーナイトなし） |
| 随時 | 当日の損失が `guardrails.md` の「1日の最大損失額」に達したら成行決済して当日終了（キルスイッチ） |

- **順張り**である点（＝将来予測ではなく「すでに上がっている銘柄に短期で乗る」）を note/SNS でも明記する。
- 「始値基準」で指値を出す（`stock-app` の管理画面は前日終値基準の %。bot 側で始値から再計算するか、
  前日終値基準にそろえるかは社長が確定）。
- **売買区分＝信用取引**（社長確認済み 2026-09-12。前回「現物」と記載したのは誤りで訂正）。
  同日中に新規建て→返済（日計り）を完結させる想定で、多くの証券会社が日計り信用に手数料・金利優遇を
  設けているため、現物より低コストで回せる可能性が高い（**実際の手数料・金利体系は口座開設後にkabuステーション/
  eスマート証券の案内で確認し、下の表に反映する**）。
  信用取引には現物にない固有のリスクがあるため、`guardrails.md` に以下を追加で確定する:
  - **委託保証金率とレバレッジ**: 投入額に対して建てられる玉が大きくなる分、同じ%の逆行でも
    現物より損失が大きくなる。1トレードの最大損失額は「建玉サイズ×損切り%」で計算し、保証金額基準ではないことに注意
  - **追証（保証金維持率）ライン**: 想定外の急変で維持率を割り込むと追加保証金や強制決済が発生する。
    キルスイッチの損失額は、追証ラインに達するよりずっと手前で発動するように設定する
  - **制度信用／一般信用の別**: 対象銘柄が信用取引可能かの事前チェックをbot側の除外条件に追加
  - 前場のみで手仕舞う設計のため金利（品貸料）はほぼ発生しない想定だが、日計り信用の手数料体系を確認して明記する

## bot 側でも二重チェックする除外

- ストップ高/安の張り付き・値幅制限で買えない/売れない
- 当日が決算発表日の銘柄
- 気配・板が薄く指値が通らない
- 前日終値と始値の乖離が大きすぎる（ギャップアップしすぎ＝寄り天リスク。閾値は `guardrails.md`）

## v1 で決めておくこと（`guardrails.md`）

- 1回の投入額（＝実質「運用総資金」に近い。1銘柄なので）
- 買い指値の置き方（始値そのもの／始値 +α まで許容）
- 利確 X% ／ 損切り Y%
- 前場引けの強制決済時刻（11:30 の何分前に発注するか）
- 1日の最大損失額（キルスイッチ）
- ギャップアップの許容上限

## 検証（未実施・社長が段階導入）

- v1 はバックテストせず、**発注しないログモード**で数日 →
  **kabuステーションの検証用APIパスワードでの試験発注**（本番資金を動かさずに注文コードパスを確認。
  `kabu-api-notes.md` 参照）→ 最小ロットで本番実発注、と段階導入。
- kabuステーションの「ソフトリミット」を投入額に見合う額まで下げてから本番に入る（`guardrails.md`）。
- 記録は `trade/journal/YYYY-MM.md`。想定（シグナルどおり動いたか）と実績（滑り・約定率・損益）を分けて書く。
- `stock-app` 側にすでに「月次勝率」があるので、bot の実損益とアプリの理論勝率の乖離を毎週見る。

## v2 以降の検討

- 1銘柄 → 複数銘柄・資金分散
- トレーリングストップ／分割エグジット
- 前場の値動きを数分見てからのエントリー（寄り天を避ける）
- 後場も使う（前場完結をやめる）
- セクター偏りの制限（`stock-app` の改善候補と共通）
