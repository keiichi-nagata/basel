# トレード部 — 戦略メモ

売買の根拠をここに残す。実装は別リポの bot 本体（`投資` monorepo の `daytrade-bot/`、`stock-app` と同じ場所）。
**Claude Code / trade-ops は戦略・コードのドラフトまで。発注はしない。**

**設計の置き場所の分担**: この戦略・パラメータの「意味」の定義は Basel（このファイル・`guardrails.md`）が
持つ。実際に bot が読み込む設定ファイルの実体・売買履歴のログは `投資/daytrade-bot/`（GitHub管理）に置く
（Basel外・API認証情報と同じ理由）。このファイルの表の項目名と、daytrade-bot の設定ファイルのキー名は
一致させる。

## 全体像（v1.1・社長方針 2026-09-12。複数銘柄・GitHub設定駆動に更新）

**複数銘柄・前場だけで完結**する順張りデイトレを自動化する（v1の「1日1銘柄」から拡張）。

| 時刻 | 何をする |
|---|---|
| 7:00 | `stock-app` が **おすすめ株を最大10位まで** 順位付きで選定（`recommendations`）。日によっては0件（「おすすめ無し」）もある。スコア＝直近5営業日モメンタム＋出来高急増度、フィルタ＝5日MA>20日MA・RSI14<70・直近採用済み除外 |
| 9:00〜 | bot が設定ファイル（下記）の条件で当日の買付銘柄を確定 → **始値を確認** → 銘柄ごとに始値基準の**買い指値**と**損切り逆指値**を出して新規建て（信用）。約定しなければその銘柄は当日見送り（追いかけない） |
| 約定後 | 銘柄ごとに **利確の売り指値**（始値 +X%）と **損切りの逆指値**（始値 −Y%）を置く |
| 11:15ごろ（前場引けの少し前） | 利確・損切りどちらも当たっていない建玉を、**成行で決済**（v1.1は前場のみで完結・オーバーナイトなし。設定上は後場15:15決済も選べる作りにするが、当面は前場固定で運用し、実績を見てから検討） |
| 随時 | 当日の損失合計が `guardrails.md` の「1日の最大損失額」に達したら、残る建玉をすべて成行決済して当日終了（キルスイッチ） |

## 購入条件の設定画面（`投資/daytrade-bot/` 側の実体）

毎朝9:00に bot が読み込む。値の変更は社長が行う（`docs/decisions/0005` の絶対ルール）。
**stock-appの管理画面と同じ方式**（Streamlit + Supabaseのフォーム画面）で設定する
（GitHub上のファイル直接編集ではない。2026-09-12訂正: 当初YAMLファイル方式で作ったが、
社長の想定と違ったためWeb画面に作り直した）。実体は `投資/daytrade-bot/pages/1_設定.py`、
データは Supabase の `daytrade_settings` テーブル。
`mode: log_only/paper/live` の3段階を持ち、`common/validate.py` が
paper/live 移行前に全項目確定済みかを検証し、未確定なら保存をブロックする（安全弁）。
セットアップ手順は `投資/daytrade-bot/README.md` 参照。

| 項目 | 内容 | 備考 |
|---|---|---|
| 購入件数（上限） | 整数（例: 3） | `stock-app` の順位上位からこの件数まで採用。候補がこれより少ない日は少ない件数（0件もあり） |
| 市場フィルタ | すべて／スタンダード／プライム／グロース | この区分でフィルタしたうえで順位上位を採用。`stock-app`が銘柄ごとの市場区分を持っている前提（J-Quants由来） |
| 1銘柄あたりの予算額 | 円（例: 【要確認】円） | **株数はここから逆算**（社長方針 2026-09-12）: 株数 = floor(予算額 ÷ 始値 ÷ 100) × 100（単元株＝100株単位に切り捨て）。予算額に対し100株も買えない銘柄は**その日は見送り** |
| 利確ライン | 始値 ＋X%（例: +3%） | 指値価格は円未満を四捨五入して整数円にする。**注意**: 呼値（最小価格変動単位）は価格帯によって1円より大きい場合がある（TSEの呼値表）。単純な四捨五入だと呼値に乗らず発注が弾かれる可能性があるため、bot側で呼値表に合わせた丸めが必要か別途検証する【要確認】 |
| 損切りライン | 始値 −Y%（例: −2%） | 同上の丸めの注意点あり |
| 決済セッション | 前場（11:15めど）／後場（15:15めど） | **当面は「前場」に固定**（社長方針 2026-09-12）。実績を見てから後場を検討。設定ファイル上はどちらも選べる作りにする |

- **順張り**である点（＝将来予測ではなく「すでに上がっている銘柄に短期で乗る」）を note/SNS でも明記する。
- 「始値基準」で指値を出す（`stock-app` の管理画面は前日終値基準の %。bot 側で始値から再計算する）。
- **売買区分＝信用取引**（社長確認済み 2026-09-12）。同日中に新規建て→返済（日計り）を完結させる想定で、
  多くの証券会社が日計り信用に手数料・金利優遇を設けているため、現物より低コストで回せる可能性が高い
  （実際の手数料・金利体系はeスマート証券の案内で確認し、下の表に反映する）。
  信用取引固有のリスク（委託保証金率・レバレッジ、追証ライン、制度信用/一般信用の別）は `guardrails.md` に記載。

## 売買履歴の置き場

`投資/daytrade-bot/` 側にログ（GitHub管理・社長がいつでも確認できる）。Basel の `trade/journal/` には
**週次・月次のサマリ**（勝率・損益・気づき）だけを記録し、生ログは持ち込まない（実装は daytrade-bot 側）。

## bot 側でも二重チェックする除外

- ストップ高/安の張り付き・値幅制限で買えない/売れない
- 当日が決算発表日の銘柄
- 気配・板が薄く指値が通らない
- 前日終値と始値の乖離が大きすぎる（ギャップアップしすぎ＝寄り天リスク。閾値は `guardrails.md`）
- 信用取引不可の銘柄（`guardrails.md`）

## v1.1 で決めておくこと（`guardrails.md`）

- 1銘柄あたりの予算額（＝購入件数×予算額が実質「1日に張る最大額」）
- 買い指値の置き方（始値そのもの／始値 +α まで許容）
- 利確 X% ／ 損切り Y%、および指値価格の丸め方（呼値対応）
- 決済セッション（前場固定・11:15の何分前に発注するか）
- 1日の最大損失額（キルスイッチ）／週の最大損失額
- ギャップアップの許容上限
- 購入件数の上限・市場フィルタの初期値

## 検証（未実施・社長が段階導入）

- v1.1 はバックテストせず、**発注しないログモード**で数日 →
  **kabuステーションの検証用APIパスワードでの試験発注**（本番資金を動かさずに注文コードパスを確認。
  `kabu-api-notes.md` 参照）→ 最小ロット・少ない購入件数（例: 1件）で本番実発注 → 徐々に件数を増やす、と段階導入。
- kabuステーションの「ソフトリミット」を（予算額×購入件数）に見合う額まで下げてから本番に入る（`guardrails.md`）。
- 記録は `trade/journal/YYYY-MM.md`。想定（シグナルどおり動いたか）と実績（滑り・約定率・損益）を分けて書く。
- `stock-app` 側にすでに「月次勝率」があるので、bot の実損益とアプリの理論勝率の乖離を毎週見る。

## v2 以降の検討

- トレーリングストップ／分割エグジット
- 前場の値動きを数分見てからのエントリー（寄り天を避ける）
- 後場決済の本格導入（v1.1で実績を見てから）
- セクター偏りの制限（`stock-app` の改善候補と共通）
- 銘柄ごとの予算額の傾斜配分（スコア上位により多く張るなど）
