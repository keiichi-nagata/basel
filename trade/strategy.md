# トレード部 — 戦略メモ

売買の根拠をここに残す。実装は別リポの bot 本体（`投資` monorepo の `daytrade-bot/`、`stock-app` と同じ場所）。
**Claude Code / trade-ops は戦略・コードのドラフトまで。発注はしない。**

## 全体像（v1 のたたき台。社長が確定）

「おすすめ株アプリ（`投資/stock-app`）が毎朝出す候補銘柄を、寄り付きで買い、当日中に決済する
順張りデイトレを完全自動化する」。

- **シグナル源**: `stock-app` が毎朝 JST 7:00 に選ぶ `recommendations`（1〜5銘柄）。
  スコア＝直近5営業日モメンタム＋出来高急増度。フィルタ＝5日MA>20日MA・RSI14<70・直近2営業日採用済み除外。
  → **将来予測ではなく「すでに上がっている銘柄を短期で乗る」順張り**である点を、note/SNSでも明記する。
- **bot の役割**: 8:30〜寄り付き前に `recommendations`（Supabase）を読む → 資金配分を計算 →
  寄り成り（または寄り付き直後の指値）で新規買い → 利確の指値と損切りの逆指値を同時に置く（OCO相当）→
  引け前に未約定ぶんを成行で全決済（オーバーナイトしない）。

## エントリー（v1）

- 対象: 当日の `recommendations` 全銘柄（最大5）。`stock-app` 側で市場区分・株価帯・最低出来高
  （デフォルト5万株）・IPO直後除外は済んでいる前提。
- タイミング: 寄り付き（9:00）。寄り成りは滑りが読めないため、v1は「前日終値 +0.5% までの指値」で入り、
  約定しなければ見送り（追いかけない）。
- サイズ: 1銘柄あたり `guardrails.md` の「1銘柄あたりの最大投入額」を上限に、
  `運用総資金 ÷ 想定同時保有数` で等額。単元未満は切り捨て。
- 除外（bot 側でも二重チェック）:
  - ストップ高/安の張り付き、値幅制限で買えない/売れない銘柄
  - 当日が決算発表日の銘柄（`stock-app` の今後の改善候補にもある。bot 側で決算カレンダーを確認）
  - 気配・板が薄く指値が通らない銘柄

## エグジット（v1）

- **利確**: 前日終値 +3%（`stock-app` の管理画面デフォルト）を指値。社長が管理画面で変えたら追随。
- **損切り**: 前日終値 −2% を逆指値。**1トレードの最大損失＝この幅 ×株数** を超えないこと。
- **時間切れ**: 14:55 までに利確・損切りどちらも当たらなければ、成行で全決済（デイトレ厳守）。
- **キルスイッチ**: 当日の実現損益＋含み損が `guardrails.md` の「1日の最大損失額」に達したら、
  全銘柄を成行決済して当日は新規停止。

## 検証（未実施・社長が段階導入）

- v1 はバックテストせず、まず**発注しないログモード**で数日 → 最小ロットで実発注、と段階導入。
- 記録は `trade/journal/YYYY-MM.md`。想定（シグナルどおり動いたか）と実績（滑り・約定率・損益）を分けて書く。
- `stock-app` 側にすでに「月次勝率」があるので、bot の実損益とアプリの理論勝率の乖離を毎週見る。

## v2 以降の検討

- 寄り付き一括ではなく分割エントリー／トレーリングストップ
- セクター分散（`stock-app` の改善候補と共通）
- 前場の値動きを見てからのエントリー（寄り天を避ける）
