# 企画部

## 役割

リサーチして新しいnoteネタを企画。スコアが高いものを開発部へ提案。

## 週次の流れ（月曜）

1. `researcher` エージェントに直近トレンド・検索需要・SNS話題を収集させる
2. 候補を `ideas.md` に追記（スコア付き）
3. 社長がレビューし、採用したものを該当開発部の README / STATE.md に反映
4. 却下・保留はステータスを更新して `ideas.md` に残す（後で再評価）

## スコアリング基準（各5点、合計25点満点）

| 観点 | 5点 | 1点 |
|---|---|---|
| 需要 | 明確な検索需要 / 話題性がある | 誰が読むか不明 |
| 差別化 | AIに出せない独自の観点がある | どこでも読める内容 |
| 収益化 | 有料note or 相性の良いアフィリに直結 | 収益への線が引けない |
| 運用コスト | 既存の型を流用でき軽い | 新規の仕組みが必要で重い |
| リスク | データ出所・規約がクリア | 権利・規約が怪しい |

- 合計18点以上 → 開発部へ提案
- 12〜17点 → 保留（次回再評価）
- 11点以下 → 却下
