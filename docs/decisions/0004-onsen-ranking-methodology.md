# 0004 — 開発4部 温泉ランキングの定義・口コミの書き方・アフィリエイト

日付: 2026-09-05
状態: 採用
関連: [[0002-drama-ranking-methodology]]

## 決定

### 1. クレーム
「〔エリア〕温泉 宿ランキングTOP5（独自採点）」「総合評価が高い順」とする。
「一番人気」「絶対おすすめ」等の断定・優良誤認を招く表現はしない。

### 2. 独自採点の定義
楽天トラベルの宿泊者評価（5点満点） ＋ じゃらんの宿泊者評価（5点満点）の**単純平均**。
両方が取得できる宿のみ対象、かつ各サイトで口コミ**20件未満**の宿は対象外とする
（少数レビューからの過大な一般化を避ける）。表にはA/Bの内訳（点数・件数）を併記する。

### 3. 口コミの書き方（コンプライアンス上、最重要の決定）
**実際に宿泊したかのような一人称の体験談としては書かない。** 口コミサイトの傾向を
「口コミでは〜という声が多い」「一方で〜という指摘も」という**第三者視点の要約**で書く。
特定の口コミ本文の丸写しも禁止し、複数の口コミに共通する傾向を自分の言葉でまとめる。

### 4. アフィリエイト
- 楽天トラベル: 個別宿の予約リンク＋汎用トップリンクの両方を掲載したいが、**楽天アフィリエイト未登録**
  のため、登録が完了するまではテキスト表記のみ
- JTB旅行予約: A8経由で**提携済み**。汎用トップリンクのみ掲載（個別宿の深いリンクはA8のJTB案件では
  提供されない想定）
- 個別宿の楽天トラベルリンクは月ごとに変わるため `affiliates.json`（汎用リンクのみ管理）では持たず、
  各月の `drafts/YYYY-MM.md` に直接埋め込む

### 5. 自動化
収集の自動パイプラインは**作らない**。楽天トラベル・じゃらんの評価API連携やスクレイピングは
規約・実装コストに対してメリットが薄いため、`ranking-writer` がWebSearchで毎月手動リサーチする
（開発2/3部の自動収集とは異なる運用）。

## 理由

- ユーザーの当初案は「口コミをもとに自分が宿泊してきたように書く」だったが、実際に宿泊していない
  体験を事実として書くことは景品表示法のステマ規制・優良誤認表示のリスクが高く、アフィリエイト
  リンクを併記するとなおさら問題になる。同じ価値（リアルな良い点・残念な点）は第三者視点の要約でも
  十分に出せるため、要約方式を採用（社長確認済み、2026-09-05）。
- 採点ソースは開発3部の「複数の公開指標を単純平均する」という前例を踏襲し、楽天トラベル＋じゃらんの
  評価点数（どちらも一次情報・URL明記可能）を採用（社長確認済み、2026-09-05）。
- 温泉宿の評価データは自販連/全軽自協のような一括ダウンロード可能な統計が無く、TVer/Netflixのような
  週次スクレイピング対象にも向かないため、自動化コストに見合わない。WebSearchでの都度リサーチとする。

## 影響・保留事項

- 楽天アフィリエイト未登録のため、当面は個別宿・汎用とも楽天トラベルのリンクはテキスト表記のみで
  開始する（登録後、遡って過去号にもリンクを追加するかは別途判断）。
- 最低口コミ件数（20件）は初期値。エリアによっては該当宿が少なくTOP5が埋まらない可能性があり、
  その場合は閾値の見直しを検討する。
- じゃらんの評価点数のWebSearch取得が不安定な場合、楽天トラベル単独採点に一時的に切り替える
  可能性がある（`sources.md` を更新して対応）。
