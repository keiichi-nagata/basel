# 0005 — トレード部（自動デイトレード）を新設する

日付: 2026-09-10
状態: 採用

## 決定

社長が並行して始める「kabuステーションAPI（三菱UFJ eスマート証券）による完全自動デイトレード」を
**Basel の新部門「トレード部」として実施する**。収益源は相場での売買損益（自己資金・自分の口座のみ）。

関連する2つの有料note（「おすすめ株アプリの作り方」「デイトレード完全自動化のやり方」）は
**開発1部**で扱う（`dev/1-apps/catalog.md` #7-8）。トレード部は運用そのもの、開発1部は
そのやり方を売る有料note、という切り分け。

| 対象 | 部門 | 収益 |
|---|---|---|
| 自動デイトレの運用（戦略・発注・売買損益・運用日誌） | **トレード部** | 売買損益 |
| 有料note 2本（作り方・自動化のやり方） | 開発1部 | note販売（`paid_note`） |
| 構築記録・実績の SNS 発信 | マーケ部 | 集客 |

## 配置

- **Baselリポジトリ `trade/`**: 戦略メモ／ガードレール（リスク上限の明文化）／kabu-api-notes／
  運用日誌／実績サマリ／週次レビュー。
- **bot 本体コード・kabuステーションAPI認証情報・実行環境**: **`投資` monorepo の `daytrade-bot/`**
  （2026-09-10 決定）。`stock-app` と同じ場所に置き、おすすめ選定ロジックを直接呼べるようにする。
  認証情報は `daytrade-bot/.env`（git管理外）。Basel のリポジトリ・CI には証券APIの秘密情報を置かない。
- **実行環境**: kabuステーションAPIはデスクトップアプリ経由のため、**常時起動のWindows環境**が要る
  （`stock-app` の GitHub Actions 完結型とは異なる）。

## 絶対ルール（`CLAUDE.md` に追記）

自動売買は設計上「証券APIへ自動発注する行為」が中心で、Basel の既定ルール（外部へのAPI送信は
社長承認後・エージェントはドラフトまで）と衝突する。トレード部だけの運用ルールを定める:

- 自動発注は、**社長が承認した戦略と、明文化されたリスク上限の範囲内**でのみ専用スクリプトが実行する。
- 明文化する上限: ①1銘柄あたりの最大投入額 ②1日の最大損失額（到達で自動停止＝キルスイッチ）
  ③稼働時間帯 ④対象銘柄 ⑤運用に回す総資金。
- これらの**変更、bot の稼働／停止の切替は社長承認必須**。
- **エージェント・Claude Code は、コード・戦略のドラフトと運用日誌の作成のみ**。発注・パラメータ変更・
  稼働切替・APIキーの取り扱いは一切しない。

## 経理

- トレード部の売買損益は Basel の事業損益として管理するが、**確定申告上の所得区分（事業所得か
  譲渡所得＝申告分離課税か）は税理士に確認**する。株のデイトレ益を事業所得と認めさせるハードルは
  高い（原則は譲渡所得）。
- `finance/` では売買損益を SNS 事業の売上・経費と混同しないよう、別カテゴリ／別集計にする
  （`finance/README.md`）。
- 開発1部の note 販売売上は従来どおり `paid_note`。

## 規制の宿題（社長）

- 運用は自分の口座のみ。**他人資金の運用・シグナル販売**を始める場合は金融商品取引業
  （投資助言・運用業）の登録要否を要確認。
- kabuステーションAPI の利用規約（自動売買条件・発注頻度制限）を運用開始前に確認する。

## 仕組み（v1・社長方針 2026-09-10・`trade/strategy.md`）

**1日1銘柄・前場だけで完結**。`stock-app`（毎朝 JST 7:00 におすすめ株を1銘柄選定）→ Supabase
`recommendations` → `daytrade-bot` が 9:00 に始値を確認 → 始値基準の指値で新規買い＋損切り逆指値 →
利確/損切りが当たらなければ 11:30 の前場引けで成行決済 → 日次損失が上限で当日キルスイッチ。

## 影響・保留事項

- リスク上限の初期値は未確定（`trade/guardrails.md` の `【要確認】`、社長が確定）。
- bot は `投資/daytrade-bot/`。kabuステーションと bot は**この Claude Code が動く PC**で常時起動
  （2026-09-10 決定）。Claude/エージェントは発注・稼働操作を一切しない。
- 三菱UFJ eスマート証券の口座開設待ち。開設後に着手。
- 実績が出るまでトレード部の収益はゼロ計上。損失が出た月もそのまま記録する。
